# 학습: 스택과 큐 (LIFO·FIFO)

> 관련 문서: [학습_정렬](학습_정렬.md) · [학습_DFS](학습_DFS.md) · [학습_해시](학습_해시.md) · [학습_BFS](../problems/programmers/lv2/006_게임_맵_최단거리/학습_BFS.md)

DFS·BFS를 하면서 여러분은 이미 **스택과 큐를 써 왔습니다** — 다만 이름을 붙여 정리하지 않았을 뿐입니다.
이 문서는 그 둘을 자료구조로서 제대로 정리합니다. 새로 배우는 것이라기보다, **이미 손에 익은 것에 이름을 붙이는** 작업에 가깝습니다.
예제는 전부 중립 소재로 만들었고, 아래 모든 출력값은 실제로 실행해 검증한 값입니다.

## 1. 스택과 큐란 — LIFO vs FIFO

둘 다 "원소를 넣고 빼는 통"인데, **어느 쪽으로 빼느냐**가 정반대입니다.

| | 스택 (Stack) | 큐 (Queue) |
|---|---|---|
| 규칙 | **LIFO** (Last In, First Out) | **FIFO** (First In, First Out) |
| 한 마디로 | **나중에** 넣은 게 **먼저** 나옴 | **먼저** 넣은 게 **먼저** 나옴 |
| 비유 | 접시 쌓기 (맨 위부터 꺼냄) | 매표소 줄서기 (앞사람부터) |
| 넣고 빼는 곳 | **같은 쪽**(위)에서 넣고 뺌 | **반대쪽**(뒤로 넣고 앞으로 뺌) |

- **스택**: 책상에 책을 쌓으면, 꺼낼 땐 **맨 위(마지막에 올린 것)** 부터 꺼냅니다. 아래 책은 위를 다 치워야 나옵니다.
- **큐**: 줄을 서면 **먼저 온 사람**부터 처리됩니다. 새로 온 사람은 뒤에 붙습니다.

### 사실 우리는 이미 둘 다 써 왔다 — DFS와 BFS

되돌아보면 두 자료구조는 이미 등장했습니다.

- **DFS = 스택**. [학습_DFS](학습_DFS.md)에서 "재귀 호출 스택이 곧 걸어온 길"이라고 했죠. `dfs(a)` 안에서 `dfs(b)`를 부르면 b가 **먼저 끝나야** a로 돌아옵니다 — **나중에 부른 게 먼저 끝나는**, 정확히 LIFO입니다. 재귀가 스택을 자동으로 굴려 준 것입니다.
- **BFS = 큐**. [학습_BFS](../problems/programmers/lv2/006_게임_맵_최단거리/학습_BFS.md)에서 `deque`로 "먼저 발견한 칸을 먼저 처리"했습니다. 거리 1을 전부 넣으면 거리 1이 전부 먼저 나오는 것 — 정확히 FIFO입니다.

> **한 줄 정리:** 스택은 "**마지막 것부터**"(LIFO), 큐는 "**처음 것부터**"(FIFO). DFS가 스택으로, BFS가 큐로 돌아갔던 이유가 바로 이 순서 차이였습니다.

## 2. 파이썬으로 구현 — `list` vs `deque`

파이썬은 스택·큐 전용 클래스를 따로 안 씁니다. **스택은 `list`, 큐는 `collections.deque`** 로 만듭니다.

### 스택 — `list`의 `append` / `pop`

리스트의 **끝**에 넣고, **끝**에서 뺍니다. 둘 다 O(1)입니다.

```python
stack = []
stack.append("A")     # 넣기(push)  -> [A]
stack.append("B")     #             -> [A, B]
stack.append("C")     #             -> [A, B, C]

top = stack.pop()     # 빼기(pop) — 맨 끝(마지막에 넣은 C)이 나옴
print(top)            # C
print(stack)          # ['A', 'B']
print(stack[-1])      # B   ← 꺼내지 않고 맨 위만 훔쳐보기(peek)
```

- `append(x)` — 위에 쌓기(push)
- `pop()` — 맨 위 꺼내기(인자 없이 쓰면 **끝** 원소, LIFO)
- `stack[-1]` — 꺼내지 않고 맨 위만 확인(peek)

### 큐 — `collections.deque`의 `append` / `popleft`

**뒤**로 넣고 **앞**에서 뺍니다.

```python
from collections import deque

q = deque()
q.append("A")         # 뒤에 넣기   -> [A]
q.append("B")         #             -> [A, B]
q.append("C")         #             -> [A, B, C]

first = q.popleft()   # 앞에서 빼기 — 먼저 넣은 A가 나옴
print(first)          # A
print(list(q))        # ['B', 'C']
```

- `append(x)` — 뒤에 넣기
- `popleft()` — 앞에서 꺼내기(FIFO)

### ⚠️ 큐에 `list.pop(0)`을 쓰면 안 되는 이유 (다시 강조)

[학습_BFS](../problems/programmers/lv2/006_게임_맵_최단거리/학습_BFS.md) 2절에서 짚었던 함정입니다. `list`로도 `pop(0)`으로 앞을 뺄 수는 **있지만**, 느립니다.

```python
lst = [1, 2, 3]
print(lst.pop(0))     # 1   (동작은 됨)
print(lst)            # [2, 3]
```

`list.pop(0)`은 **맨 앞을 빼면 나머지 원소를 전부 한 칸씩 앞으로 당겨야** 해서 **O(n)** 입니다. 큐를 이걸로 만들면 원소 하나 뺄 때마다 전체를 훑게 되어, N개 처리에 O(N²)로 느려집니다.
`deque.popleft()`는 앞을 빼도 당길 필요가 없어 **O(1)** 입니다. **큐는 항상 `deque`** — 이 원칙은 BFS에서든 대기열 처리에서든 똑같습니다.

| 하는 일 | `list` | `deque` |
|---|---|---|
| 끝에 넣기 `append` | O(1) | O(1) |
| 끝에서 빼기 `pop()` (스택) | **O(1)** ✅ | O(1) |
| 앞에서 빼기 (큐) | `pop(0)` → **O(n)** ⚠️ | `popleft()` → **O(1)** ✅ |

정리하면: **스택은 `list`로 충분**(양 끝 중 끝만 쓰니까), **큐는 반드시 `deque`**(앞에서 빼야 하니까).

## 3. 스택이 빛나는 순간 — "직전 것을 되돌아봐야 할 때"

스택을 떠올려야 하는 신호는 셋입니다.

- **짝 맞추기**: 여는 것과 닫는 것이 짝을 이루는 구조(괄호 등).
- **직전 것을 되돌아봐야 할 때**: 방금 처리한 것과 지금 것을 비교해 취소·상쇄하는 경우.
- **최근 것부터 처리**: 가장 나중에 들어온 것을 먼저 꺼내야 할 때.

공통점은 **"가장 최근 것"이 관심 대상**이라는 것입니다. 그게 곧 스택의 맨 위(`[-1]`)입니다.

### 대표 예시 — 여닫이 짝 맞추기 (스택의 교과서 예제)

스택의 가장 유명한 쓰임은 **여는 기호와 닫는 기호가 올바르게 짝을 이루는지** 검사하는 것입니다. 원리만 보면 이렇습니다.

- **여는 기호**를 만나면 스택에 **쌓는다**.
- **닫는 기호**를 만나면, 스택 맨 위(가장 최근에 연 것)를 꺼내 **짝이 맞는지 확인**한다.

왜 스택인가? 나중에 연 것이 **먼저 닫혀야** 올바른 중첩이기 때문입니다(`([])`는 되지만 `([)]`는 안 됨). "가장 최근에 연 것부터 닫는다" = LIFO = 스택이 딱 맞습니다.

아래는 여러 종류의 여닫이 기호를 다루는 **일반화된 골격**입니다(특정 문제 풀이가 아니라 스택의 원리 시연입니다).

```python
def brackets_balanced(s):
    pairs = {")": "(", "]": "[", "}": "{"}   # 닫는 → 짝이 되는 여는
    stack = []
    for ch in s:
        if ch in "([{":
            stack.append(ch)                  # 여는 기호는 쌓는다
        elif ch in ")]}":
            if not stack or stack.pop() != pairs[ch]:
                return False                  # 짝 없이 닫히거나, 짝이 안 맞음
    return not stack                          # 안 닫힌 게 없어야 완전한 짝

print(brackets_balanced("([])"))     # True   (올바른 중첩)
print(brackets_balanced("([)]"))     # False  (교차 — 최근 연 [ 가 먼저 안 닫힘)
print(brackets_balanced("(("))       # False  (안 닫힘 — 끝에 스택이 안 빔)
print(brackets_balanced(""))         # True   (빈 입력은 균형)
```

두 가지 실패를 스택이 어떻게 잡는지 보세요.
- `([)]` 는 `)`를 만났을 때 맨 위가 `[`(가장 최근 연 것)라 짝(`(`)이 안 맞아 실패.
- `((` 는 끝까지 왔는데 스택에 `(`가 남아 있어(안 닫힘) `not stack`이 False → 실패.

> **핵심:** "**가장 최근 것**"을 되돌아봐야 하면 스택입니다. 맨 위(`stack[-1]`, `stack.pop()`)가 곧 "직전에 처리한 것"이라, 짝 맞추기·상쇄·중첩 검사에 자연스럽게 들어맞습니다.

## 4. 큐가 빛나는 순간 — "먼저 온 것부터 처리"

큐를 떠올려야 하는 신호는 **"순서를 지켜 먼저 온 것부터 처리한다"** 입니다.

- **대기열**: 매표소·프린터 작업처럼 **온 순서대로** 서비스하는 경우.
- **BFS 확장**: 시작점에서 **가까운 것(먼저 발견한 것)부터** 겹겹이 퍼지는 탐색.

### 대표 예시 — 대기열 처리

먼저 온 것부터 하나씩 꺼내 처리하면, `deque`가 순서를 자동으로 지켜 줍니다.

```python
from collections import deque

waiting = deque(["1번", "2번", "3번"])   # 온 순서대로 줄 세움
served = []
while waiting:                           # 큐가 빌 때까지
    served.append(waiting.popleft())     # 앞에서 꺼내 처리(FIFO)
print(served)                            # ['1번', '2번', '3번']
```

넣은 순서(`1번 → 2번 → 3번`)가 처리 순서로 그대로 유지됩니다. 이게 FIFO의 보장입니다.
만약 중간에 "지금 것은 아직 처리 못 하니 **맨 뒤로 다시 보낸다**" 같은 규칙이 있으면, 꺼낸 것을 다시 `append`해 뒤로 돌리면 됩니다 — 큐 하나로 "순서 유지 + 미룸"이 표현됩니다.

### BFS 확장은 이미 해봤다

[학습_BFS](../problems/programmers/lv2/006_게임_맵_최단거리/학습_BFS.md)의 물결 퍼짐이 정확히 이 큐입니다. "거리 1인 것들을 먼저 다 큐에 넣으면 거리 1이 먼저 다 나온다" — 대기열과 완전히 같은 원리로, 큐의 FIFO가 **겹 순서**를 지켜 줬습니다.

> **핵심:** "**먼저 온 순서를 지켜** 처리한다"가 보이면 큐(`deque`)입니다. 대기열이든 BFS 겹 퍼짐이든, `append`로 뒤에 넣고 `popleft`로 앞에서 빼는 골격이 그대로 쓰입니다.
