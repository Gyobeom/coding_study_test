# 학습: 해시 (딕셔너리·집합)

> 관련 문서: [학습_DFS](학습_DFS.md) · [학습_BFS](../problems/programmers/lv2/006_게임_맵_최단거리/학습_BFS.md) · [학습_문자열_구현](학습_문자열_구현.md)

지금까지는 그래프·격자를 **DFS/BFS**로 훑었습니다. 이 문서에서 **해시(파이썬 `dict`·`set`)** 라는 새 도구를 익힙니다.
해시는 "**키만 주면 값을 즉시 찾아 주는 표**"입니다. 앞으로 나올 문제 상당수가 "무엇을 키로 삼을지"만 정하면 풀리는 형태라, 이 도구가 2주차의 중심입니다.
예제는 전부 **중립 소재(과일·학생 명단 등)** 로 만들었고, 아래 모든 출력값은 실제로 실행해 검증한 값입니다.

---

## 1. 해시란 무엇인가 — "키로 즉시 찾는다"

리스트에서 "체리가 있나?"를 확인하려면 **앞에서부터 하나씩** 비교해 봐야 합니다.

```python
fruits = ["사과", "바나나", "체리", ...]   # n개
if "체리" in fruits:   # 최악의 경우 n개를 전부 훑는다 → O(n)
    ...
```

원소가 많아질수록 느려집니다. 해시는 이 탐색을 **한 번에** 끝냅니다.

- **리스트 순차 탐색**: "몇 번째에 있나?"를 몰라 처음부터 훑는다 → **O(n)**
- **해시 조회**: 키를 넣으면 값이 있는 자리를 곧장 계산해 준다 → **O(1)** (평균)

비유하면 리스트는 **번호표 없는 서류 더미**(처음부터 넘겨 봐야 함)이고, 해시는 **이름표가 붙은 사물함**(이름만 알면 그 칸으로 직행)입니다.

### 사실 우리는 이미 해시를 써 왔다 — `visited`

BFS/DFS에서 쓴 `visited = [False] * n` 을 떠올려 보세요. `visited[3]` 은 "3번 노드를 방문했나?"를 **인덱스로 즉시** 읽었습니다.
이건 사실 **"인덱스가 키인 표"** 입니다 — 순서대로 훑지 않고 자리를 곧장 찾아 읽었으니까요.

`dict`는 여기서 한 걸음 나아가, **키가 정수 인덱스일 필요가 없습니다.** 문자열이든 튜플이든 키로 쓸 수 있습니다.

```python
visited = [False] * n     # 키 = 0,1,2,... 정수만 가능
seen = {}                 # 키 = "사과", ("1반","김") 등 무엇이든 가능
```

> **한 줄 정리:** `visited` 배열이 "정수 자리표"였다면, `dict`는 "**아무거나 키로 삼는 자리표**"입니다. 둘 다 "훑지 않고 곧장 찾는다"가 핵심입니다.

## 2. 파이썬 `dict` 기초

`dict`는 **키 → 값** 쌍을 담는 표입니다. 조작은 다섯 가지만 알면 됩니다.

```python
fruit_price = {"사과": 1000, "바나나": 500}   # 생성 (키:값 쌍)

print(fruit_price["사과"])          # 1000    ← 키로 조회
fruit_price["체리"] = 2000          #          ← 새 키 추가 (또는 기존 값 수정)

print("포도" in fruit_price)         # False   ← 키가 있는지 확인
print(fruit_price.get("포도", 0))    # 0       ← 없으면 기본값 0을 돌려줌

for name, price in fruit_price.items():   # 순회 (키, 값 동시에)
    print(name, price)               # 사과 1000 / 바나나 500 / 체리 2000
```

특히 두 가지를 기억하세요.

- `fruit_price["포도"]` 처럼 **없는 키를 대괄호로 조회하면 `KeyError`** 로 멈춥니다.
- `fruit_price.get("포도", 0)` 은 **없어도 안전하게 기본값**을 돌려줍니다. 다음 절 "개수 세기"의 핵심 도구입니다.

## 3. 세 가지 기본 패턴

해시 문제는 대부분 아래 셋 중 하나(또는 조합)입니다. **이 셋이 전부**라고 봐도 됩니다.

### ⓐ 개수 세기 (counting)

"각 항목이 몇 번 나오나?"를 셀 때. `get(키, 0) + 1` 관용구를 씁니다.

```python
fruits = ["사과", "바나나", "사과", "체리", "바나나", "사과"]
count = {}
for f in fruits:
    count[f] = count.get(f, 0) + 1
print(count)        # {'사과': 3, '바나나': 2, '체리': 1}
```

`count.get(f, 0)` — "이 과일이 처음이면 0에서, 이미 있으면 그 값에서" 시작해 `+1`. 없는 키를 안전하게 다루는 게 핵심입니다.

### ⓑ 존재 확인 (membership, `set`)

"이 항목이 목록에 있나?"만 중요하고 **개수·값은 필요 없을 때**는 `set`(집합)을 씁니다.
`set`은 값 없이 **키만** 담는 표라, `in` 검사가 리스트(O(n))와 달리 **O(1)** 입니다.

```python
allowed = {"사과", "바나나", "체리"}     # 중괄호에 값 없이 = set
basket = ["사과", "포도", "체리"]
result = [f for f in basket if f in allowed]   # allowed에 있는 것만 골라냄
print(result)       # ['사과', '체리']
```

리스트로 `if f in allowed_list` 를 했다면 매번 O(n)이지만, `set`이면 매번 O(1)입니다. **"있나 없나"만 볼 땐 `set`** 을 떠올리세요.

### ⓒ 키 설계 (무엇을 키로 삼을 것인가)

**해시 문제의 진짜 승부처**입니다. "무엇을 키로 삼느냐"가 곧 문제 해석입니다.
아래는 학생을 **반별로 묶는** 예입니다. 키를 "반 이름"으로 삼으면, 같은 반 학생이 자동으로 한 바구니에 모입니다.

```python
students = [("1반", "김"), ("2반", "이"), ("1반", "박")]
by_class = {}
for cls, name in students:
    by_class.setdefault(cls, []).append(name)   # 키=반, 값=이름 리스트
print(by_class)     # {'1반': ['김', '박'], '2반': ['이']}
```

`setdefault(cls, [])` — "이 반이 처음이면 빈 리스트를 만들어 두고, 그 리스트에 이름을 넣어라". `get`의 리스트 버전이라고 보면 됩니다.

> **키 설계 감각:** 같은 데이터라도 **키를 무엇으로 잡느냐**에 따라 다른 그룹이 만들어집니다.
> 반을 키로 잡으면 반별 묶음, 이름 첫 글자를 키로 잡으면 글자별 묶음이 됩니다. "무엇을 기준으로 모아야 하나?"가 곧 "키를 무엇으로 잡을까?"입니다.

## 4. `collections.Counter` 와 `defaultdict` — 위 패턴의 축약형

3절의 패턴을 손으로 익혔다면, 같은 일을 더 짧게 해 주는 도구가 있습니다. **먼저 원리(3절)를 알고 나서 쓰는 축약형**이라는 점이 중요합니다. 축약형만 외우면 왜 되는지를 놓칩니다.

### `Counter` — 개수 세기(ⓐ)의 축약형

```python
from collections import Counter
fruits = ["사과", "바나나", "사과", "체리", "바나나", "사과"]
c = Counter(fruits)
print(c)               # Counter({'사과': 3, '바나나': 2, '체리': 1})
print(c["사과"])       # 3
print(c["포도"])       # 0    ← 없는 키도 KeyError 없이 0
print(c.most_common(1))   # [('사과', 3)]   ← 가장 많은 것 뽑기
```

3절 ⓐ의 `for` + `get(f,0)+1` 를 `Counter(fruits)` 한 줄이 대신합니다. `most_common(k)` 로 "가장 많이 나온 k개"도 바로 뽑습니다.

### `Counter` 빼기 — 차집합 관용구

`Counter`끼리는 뺄셈이 됩니다. "**필요한데 아직 없는 것**"을 구할 때 유용합니다.

```python
have = Counter(["사과", "사과", "바나나"])       # 가진 것
need = Counter(["사과", "바나나", "체리"])       # 필요한 것
print(need - have)     # Counter({'체리': 1})
```

`need - have` = "필요분에서 가진 만큼을 뺀 나머지". 0 이하가 된 항목은 결과에서 **자동으로 사라집니다**(사과·바나나는 충족돼서 빠지고, 부족한 체리만 남음).

### `defaultdict` — 키 설계(ⓒ)의 축약형

3절 ⓒ의 `setdefault(cls, [])` 를 매번 쓰는 대신, 처음부터 "값의 기본형"을 정해 둡니다.

```python
from collections import defaultdict
by_class = defaultdict(list)     # 없는 키를 건드리면 빈 list가 자동 생성
for cls, name in [("1반", "김"), ("2반", "이"), ("1반", "박")]:
    by_class[cls].append(name)   # setdefault 없이 바로 append
print(dict(by_class))            # {'1반': ['김', '박'], '2반': ['이']}
```

`defaultdict(list)` 는 "없는 키에 접근하면 빈 `list`부터 깔아 준다"는 뜻입니다. `defaultdict(int)` 로 하면 개수 세기(`+1`)도 `get` 없이 됩니다.

> **정리:** `Counter`·`defaultdict`는 3절 패턴을 짧게 쓴 것뿐입니다. 원리는 같습니다 — **없는 키를 안전하게 초기화**해 주는 것.
> 손으로 `get`/`setdefault`를 쓸 줄 알면, 이 축약형은 "타이핑을 줄이는 편의"로 자연스럽게 쓰게 됩니다.

## 5. "해시 문제"를 알아보는 신호

지문에서 아래 단서가 보이면 해시(딕셔너리/집합)를 먼저 떠올립니다.

| 지문의 신호 | 떠올릴 패턴 |
|---|---|
| "**몇 개**", "**몇 번** 등장", "**빈도**", "가장 많은/적은" | ⓐ 개수 세기 (`Counter`) |
| "**포함**되어 있나", "**중복** 있나", "이미 나왔나" | ⓑ 존재 확인 (`set`, `in`) |
| "**~별로** 묶어라", "같은 것끼리 그룹" | ⓒ 키 설계 (`defaultdict`) |
| "A에는 있고 B에는 없는 것", "부족한 것" | ⓐ + `Counter` 빼기 |
| "**짝**을 찾아라", "합이 K가 되는 쌍" | ⓑ 존재 확인 (필요한 짝을 `set`에서 O(1)로 조회) |

공통 감각 하나: **"목록을 매번 처음부터 훑고 있다"** 는 생각이 들면, 그 탐색을 해시로 O(1)로 바꿀 수 있는지 의심해 보세요. 리스트 안에서 `if x in list` 를 반복문 안에서 돌리고 있다면 대개 `set`으로 바꿀 자리입니다.

## 6. 시간 복잡도 관점 — 왜 해시가 빠른가

리스트로 "겹치는 것 찾기"를 하면 이중 반복이 되어 **O(n²)** 이 되기 쉽습니다. 해시는 안쪽 탐색을 O(1)로 만들어 이를 **O(n)** 으로 낮춥니다.

| 하는 일 | 리스트로 | 해시로 |
|---|---|---|
| "x가 있나?" 1회 | O(n) (처음부터 훑음) | **O(1)** (자리 직행) |
| n개 각각에 대해 "있나?" 확인 | O(n²) | **O(n)** |
| 개수 세기 | O(n²)에 빠지기 쉬움 | **O(n)** (한 번 훑으며 `+1`) |

> BFS에서 배운 복잡도 세는 법 — **(처리 횟수) × (1회 비용)** — 이 여기서도 그대로입니다.
> n개를 한 번씩 훑고(n회), 매 회 해시 조회가 O(1)이면 전체 O(n). 리스트라면 매 회가 O(n)이라 O(n²)로 뜁니다. **"안쪽 탐색을 O(1)로 만드는 것"** 이 해시가 주는 이득입니다.
