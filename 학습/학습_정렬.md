# 학습: 정렬 (sorted·sort·key)

> 관련 문서: [학습_문자열_구현](학습_문자열_구현.md) · [학습_해시](학습_해시.md) · [학습_DFS](학습_DFS.md) · [학습_BFS](../problems/programmers/lv2/006_게임_맵_최단거리/학습_BFS.md)

지금까지는 DFS·BFS로 훑고, 해시로 즉시 찾았습니다. 이 문서에서 **정렬(sort)** 을 도구로 정리합니다.
정렬은 그 자체가 답이 되는 경우도 있지만, 진짜 힘은 **"정렬해두면 그다음이 쉬워진다"** 는 데 있습니다.
예제는 전부 중립 소재(과일·학생·숫자)로 만들었고, 아래 모든 출력값은 실제로 실행해 검증한 값입니다.
`key` 인자의 기초(길이순·튜플 key·안정 정렬)는 [학습_문자열_구현](학습_문자열_구현.md) 2·4절에서 이미 다뤘으니, 여기서는 중복을 간략히 하고 **더 깊이** 들어갑니다.

---

## 1. 정렬이란 무엇이고 왜 중요한가 — "정렬해두면 그다음이 쉽다"

정렬은 원소를 **일정한 순서(오름차순/내림차순 등)로 줄 세우는** 일입니다. 그 자체는 단순한데, 왜 알고리즘의 기본기로 꼽힐까요?

핵심은 **정렬을 해두면 탐색·비교·그리디가 전부 쉬워진다**는 데 있습니다.

- **탐색**: 뒤죽박죽인 목록에서 값을 찾으려면 처음부터 훑어야 하지만(O(n)), 정렬돼 있으면 이분탐색으로 O(log n)에 찾습니다. (이분탐색은 다음 주차 도구입니다.)
- **비교**: "중복이 있나?", "가장 가까운 두 값의 간격은?" 같은 질문은, 정렬해두면 **바로 옆 원소끼리만** 비교하면 끝납니다(4절). 정렬 안 됐으면 모든 쌍을 봐야 합니다.
- **그리디**: "가장 작은/큰 것부터 차례로 처리한다"는 전략은 애초에 **순서가 잡혀 있어야** 성립합니다.

### 우리는 이미 정렬로 순서를 보장한 적이 있다 — `여행경로`

`여행경로`(백트래킹) 문제에서 여러분은 맨 앞에 `tickets.sort()` 를 두었습니다. "가능한 경로가 여러 개면 **사전순으로 앞선** 것을 답으로 낸다"는 조건 때문이었죠.
티켓을 미리 사전순으로 정렬해두면, DFS가 **작은 것부터 순서대로** 시도하게 되어, 처음 찾은 완성 경로가 자동으로 사전순 최소가 됩니다.

> **한 줄 정리:** 정렬은 "줄 세우기" 그 자체보다, **줄을 세워 두면 뒤 작업(탐색·비교·순서 보장)이 단순해진다**는 데 가치가 있습니다. `여행경로`의 `tickets.sort()`가 바로 그 사례였습니다.

## 2. 파이썬 정렬 도구 — `sorted()` vs `list.sort()`

파이썬에는 정렬 도구가 두 개 있습니다. **무엇을 돌려주느냐**가 다릅니다.

```python
nums = [3, 1, 2]

new = sorted(nums)   # 정렬된 "새 리스트"를 반환. 원본은 그대로
print(new)           # [1, 2, 3]
print(nums)          # [3, 1, 2]   ← 원본 안 바뀜

ret = nums.sort()    # 원본을 "직접" 정렬. 반환값은 None
print(nums)          # [1, 2, 3]   ← 원본이 바뀜
print(ret)           # None
```

| | `sorted(x)` | `x.sort()` |
|---|---|---|
| 대상 | 리스트·튜플·문자열 등 **모든 순회 가능 객체** | **리스트만** (메서드) |
| 원본 | **그대로 둔다** | **직접 바꾼다**(in-place) |
| 반환 | 정렬된 **새 리스트** | **`None`** |

⚠️ 가장 흔한 실수: `result = mylist.sort()` 라고 쓰면 `result`에 `None`이 담깁니다. `sort()`는 반환이 없기 때문입니다.
"원본을 남겨두고 정렬본이 따로 필요하면 `sorted`", "원본을 그 자리에서 바꿔도 되면 `sort`"로 나눠 쓰면 됩니다.

### `reverse` — 내림차순

둘 다 `reverse=True`를 주면 내림차순이 됩니다.

```python
print(sorted([3, 1, 2], reverse=True))   # [3, 2, 1]
```

### 안정 정렬(stable)이란

파이썬 정렬은 **안정 정렬**입니다 — **key가 같은 원소끼리는 입력에 있던 순서가 그대로 유지**됩니다.

```python
data = [("김", 2), ("이", 1), ("박", 2), ("최", 1)]
print(sorted(data, key=lambda x: x[1]))
# [('이', 1), ('최', 1), ('김', 2), ('박', 2)]
```

값이 `1`인 이(李)·최(崔)가 **입력 순서 그대로**(이 → 최) 나오고, 값이 `2`인 김·박도 입력 순서(김 → 박)를 지킵니다. 이건 우연이 아니라 안정 정렬의 **보장**입니다.
왜 중요할까요? "1순위로 정렬하되, 같으면 **원래 순서**를 지켜라" 같은 요구를 **key를 건드리지 않고** 만족시킬 수 있기 때문입니다. (같으면 "원래 순서"가 아니라 "2순위 기준"으로 정렬하려면 3절의 튜플 key를 씁니다.)

## 3. `key` 인자 완전 정복 — "무엇을 기준으로 줄 세울까"

정렬의 진짜 승부처는 `key`입니다. `key`에는 **"각 원소를 무엇으로 바꿔서 비교할지"** 를 정하는 함수를 넘깁니다.
기초는 [학습_문자열_구현](학습_문자열_구현.md) 2절에 있으니 빠르게 복습하고 더 들어갑니다.

### 복습 — `key=len`, `key=lambda`

```python
words = ["bb", "a", "ccc"]
print(sorted(words, key=len))              # ['a', 'bb', 'ccc']   (길이 기준)

pairs = [("사과", 3), ("배", 1), ("감", 2)]
print(sorted(pairs, key=lambda x: x[1]))   # [('배', 1), ('감', 2), ('사과', 3)]  (둘째 원소 기준)
```

`key=len`은 "각 원소를 그 **길이**로 바꿔 비교", `key=lambda x: x[1]`은 "각 원소를 그 **둘째 값**으로 바꿔 비교". 원소 자체가 아니라 **key가 뽑아낸 값**으로 순서가 정해집니다.

### 다중 기준 — 튜플 key로 "1순위, 2순위"

"1순위로 A, 같으면 2순위로 B"는 **튜플**을 key로 돌려주면 됩니다. 튜플은 **앞 원소부터 차례로** 비교되기 때문입니다.

```python
people = [("김", 90), ("이", 80), ("박", 90)]
# 점수 내림차순, 같은 점수면 이름 오름차순
print(sorted(people, key=lambda x: (-x[1], x[0])))
# [('김', 90), ('박', 90), ('이', 80)]
```

`(-x[1], x[0])` 의 의미를 하나씩 뜯어보면:

- `-x[1]` — **1순위**: 점수. 내림차순이 필요하므로 **부호를 뒤집었습니다**(뒤 설명).
- `x[0]` — **2순위**: 이름. 1순위(점수)가 같을 때만 이 기준이 작동해 오름차순으로 갈립니다.

김(90)·박(90)은 점수가 같아 2순위인 이름으로 갈려 김 → 박 순이 됩니다. 튜플 앞자리가 먼저, 같을 때만 뒷자리 — 이 규칙이 "1순위 → 2순위"를 그대로 표현합니다.

### 내림차순 두 가지 방법 — `-x` vs `reverse`

내림차순을 만드는 길은 두 가지입니다.

```python
print(sorted([3, 1, 2], key=lambda x: -x))   # [3, 2, 1]   ← key에서 부호 뒤집기
print(sorted([3, 1, 2], reverse=True))        # [3, 2, 1]   ← reverse 플래그
```

둘 다 결과는 같지만, **다중 기준일 때 차이가 생깁니다.**

- `reverse=True` 는 **모든 기준을 통째로** 뒤집습니다. 1순위도 2순위도 전부 내림차순이 됩니다.
- `-x[1]` 처럼 key **일부만** 부호를 뒤집으면, **그 기준만** 내림차순이고 나머지는 오름차순으로 둘 수 있습니다.

그래서 위 `people` 예처럼 "점수는 내림, 이름은 오름"이 섞인 규칙은 `reverse=True`로는 못 만들고, **key 안에서 `-x[1]`로 그 자리만 뒤집어야** 합니다.
⚠️ 단, 부호 뒤집기(`-x`)는 **숫자에만** 됩니다. 문자열은 `-"김"` 이 불가능하니, 문자열 기준을 내림차순으로 하려면 다른 방법(예: 오름차순으로 정렬한 뒤 뒤집기)이 필요합니다.

> **key 감각:** `key`는 "원소를 **비교용 값**으로 바꾸는 렌즈"입니다. 렌즈가 뽑아낸 값끼리만 비교됩니다.
> 다중 기준은 **튜플**로, 내림차순은 **숫자면 `-`, 전체 뒤집기면 `reverse`** — 이 둘을 조합하면 웬만한 정렬 규칙은 한 줄로 표현됩니다.

## 4. 정렬 기반 관용구 — 줄 세운 뒤에 하는 일들

1절에서 말한 "정렬해두면 쉬워진다"를 구체적인 관용구로 봅니다. 전부 **정렬 후 옆 원소만 보면 되는** 형태입니다.

### 정렬 후 인접 비교 ① — 중복 찾기

정렬하면 **같은 값이 반드시 붙어 있게** 됩니다. 그러니 "바로 앞 원소와 같은가"만 보면 중복을 찾습니다.

```python
arr = [4, 1, 4, 2, 1]
s = sorted(arr)                              # [1, 1, 2, 4, 4]
dups = [s[i] for i in range(1, len(s)) if s[i] == s[i-1]]
print(dups)                                  # [1, 4]
```

정렬 안 된 상태에서 중복을 찾으려면 모든 쌍을 봐야 해 O(n²)이지만, **정렬해두면 한 번만 훑어(O(n)) 옆만 비교**하면 됩니다(정렬 비용 O(n log n)은 별도).

### 정렬 후 인접 비교 ② — 최소 간격

"가장 가까운 두 값의 차이"도 마찬가지입니다. 정렬해두면 **가장 가까운 값은 반드시 바로 옆에** 있습니다.

```python
xs = [1, 9, 3, 7]
s2 = sorted(xs)                              # [1, 3, 7, 9]
gap = min(s2[i] - s2[i-1] for i in range(1, len(s2)))
print(gap)                                   # 2   (3과 1의 차)
```

떨어져 있는 두 값을 볼 필요가 없습니다 — 정렬 후엔 **인접 차이 중 최소**가 곧 전체 최소 간격입니다.

### 두 리스트 정렬 후 짝짓기 — 투 포인터 맛보기

두 리스트를 각각 정렬해두면, "작은 것끼리·큰 것끼리 짝지어" 처리하기가 쉬워집니다.

```python
a = sorted([3, 1, 2])                        # [1, 2, 3]
b = sorted([30, 10, 20])                     # [10, 20, 30]
paired = [x * y for x, y in zip(a, b)]       # 작은 것끼리 곱해 짝
print(paired)                                # [10, 40, 90]
print(sum(paired))                           # 140
```

여기서는 `zip`으로 같은 자리끼리 묶었지만, 두 정렬된 리스트를 **양 끝(또는 양쪽 앞)에서 인덱스 두 개로 훑어 나가는** 방식이 **투 포인터**입니다. "정렬해두면 두 포인터로 한 번에 훑을 수 있다"가 다음에 만날 큰 주제인데, 그 출발점이 바로 이 "먼저 정렬"입니다.

> **공통 감각:** 위 관용구는 전부 **"정렬해두면 멀리 볼 필요가 없다"** 로 요약됩니다. 중복도, 최소 간격도, 짝짓기도 정렬 후엔 **옆(또는 양 끝)만** 보면 됩니다. "전부 대 전부(O(n²))로 비교하고 있다"는 느낌이 들면, 정렬로 옆만 보게 바꿀 수 있는지 의심하세요.

## 5. 시간 복잡도 — 파이썬 정렬은 O(N log N)

파이썬의 `sorted`/`sort`는 **Timsort**라는 알고리즘을 쓰며, 시간 복잡도는 **O(N log N)** 입니다(N = 원소 수).

이 숫자를 감각으로 잡아두면, "정렬을 한 번 깔고 가도 되나?"를 판단할 수 있습니다.

| N | N log N (대략) | 느낌 |
|---|---|---|
| 1,000 | 약 1만 | 순식간 |
| 100,000 | 약 170만 | 여유 |
| 1,000,000 | 약 2천만 | 무리 없음 |

그래서 제약 조건에 N이 수십만 정도라면, **일단 정렬 O(N log N)을 한 번 깔고** 그 위에서 O(N) 작업을 얹는 전략이 거의 항상 통합니다. (반면 O(N²)이면 N=100,000에서 100억 번이라 시간 초과입니다.)

### 왜 비교 정렬은 O(N log N)보다 빠를 수 없나 (직관만)

"원소끼리 크기를 비교해서" 정렬하는 방식은 이론적으로 **O(N log N)이 하한**입니다. 짧은 직관만 짚으면:

- N개를 줄 세우는 "가능한 순서"의 경우의 수는 N! 가지입니다.
- 비교 한 번은 "크다/작다" 두 갈래로 후보를 **절반씩** 좁힙니다(스무고개와 같습니다).
- N! 가지를 절반씩 좁혀 하나로 확정하려면 최소 log₂(N!)번의 비교가 필요한데, 이 값이 대략 **N log N**입니다.

즉 "비교로 순서를 알아낸다"는 방식 자체의 한계라, 어떤 영리한 비교 정렬도 이보다 근본적으로 빠를 수는 없습니다.
(값의 범위가 작을 때 쓰는 계수 정렬 같은 **비교 안 하는** 정렬은 이 하한을 비켜가지만, 그건 특수한 경우입니다.)

> **한 줄 정리:** 파이썬 정렬 = **O(N log N)**. N이 수십만이면 정렬 한 번은 부담이 안 되니, "먼저 정렬하고 시작"을 기본 전략으로 삼아도 좋습니다.
> ([학습_BFS](../problems/programmers/lv2/006_게임_맵_최단거리/학습_BFS.md) 6절의 복잡도 세는 법 — 처리 횟수 × 1회 비용 — 이 여기서도 판단 기준입니다.)

## 6. 자기 점검 체크리스트 (문서 닫기 전 스스로 답해보기)

1. `result = mylist.sort()` 라고 쓰면 `result`에 무엇이 담기는가? `sorted`와 `sort`는 원본과 반환값이 어떻게 다른가?
2. "안정 정렬"이란 정확히 무슨 뜻인가? 안정 정렬 덕분에 key를 건드리지 않고도 지킬 수 있는 요구는 어떤 것인가?
3. "점수는 내림차순, 같으면 이름은 오름차순"을 하나의 `key`로 어떻게 표현하는가? 이걸 `reverse=True`로는 왜 만들 수 없는가?
4. 정렬되지 않은 리스트에서 "가장 가까운 두 값의 간격"을 구하면 왜 O(n²)에 빠지기 쉬운가? 먼저 정렬하면 왜 인접 원소만 봐도 되는가?
5. 비교 기반 정렬이 O(N log N)보다 빠를 수 없는 이유를 스무고개(비교 한 번 = 후보 절반)에 빗대어 설명해 보라.
