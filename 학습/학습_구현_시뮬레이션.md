# 학습: 구현·시뮬레이션 (격자·좌표·상태 변화)

> 관련 문서: [학습_문자열_구현](학습_문자열_구현.md) · [학습_BFS](../problems/programmers/lv2/006_게임_맵_최단거리/학습_BFS.md) · [학습_정렬](학습_정렬.md)

[학습_문자열_구현](학습_문자열_구현.md)이 "**지문을 조건 누락 없이 옮기는** 정확성"과 문자열 도구함을 다뤘다면,
이 문서는 그 짝인 **시뮬레이션** — 격자·좌표 위에서 **상태를 규칙대로 한 스텝씩 굴리는** 유형에 무게를 둡니다.
예제는 전부 중립 소재(격자·방향·시간)로 만들었고, 아래 모든 출력값은 실제로 실행해 검증한 값입니다.

---

## 1. 시뮬레이션이란 무엇인가 — "상태를 규칙대로 굴린다"

문자열_구현 1절에서 구현 문제는 **발상 30% / 꼼꼼함 70%** 라고 정리했습니다. 시뮬레이션은 그 성격을 그대로 물려받되, 축이 하나 더 붙습니다.

- **구현(정적)**: 입력을 받아 규칙대로 **한 번** 가공해 답을 낸다. (문자열_구현이 다룬 결)
- **시뮬레이션(동적)**: 어떤 **상태**(격자 판, 좌표, 카운터 등)를 두고, 규칙에 따라 **한 스텝씩 반복해서 갱신**하다가, 멈추는 조건에서 결과를 읽는다.

즉 시뮬레이션의 뼈대는 언제나 이 모양입니다.

```
상태를 초기화한다
반복:
    현재 상태를 보고 → 규칙대로 다음 상태를 만든다
    (끝나는 조건이면 멈춘다)
최종 상태(또는 누적값)를 답으로 낸다
```

여기서 "기발한 알고리즘"은 거의 없습니다. 승부는 **규칙을 하나도 빠뜨리지 않고, 스텝의 순서를 정확히** 지키는 데 있습니다.
특히 "한 스텝에서 여러 칸이 **동시에** 바뀐다"거나 "방향을 회전한다" 같은 규칙은, 코드로 옮길 때 미묘하게 어긋나기 쉽습니다(5절).

> **한 줄 정리:** 구현이 "한 번 옮기기"라면 시뮬레이션은 "**규칙대로 반복해 굴리기**". 상태·규칙·멈춤 조건 셋을 먼저 분리해 적어두면 절반은 끝납니다.

## 2. 격자·좌표 다루기 — 판 위를 걷는 관용구

시뮬레이션 상태의 단골은 **2차원 격자**입니다. `grid[r][c]` — **행(row) r, 열(col) c**로 접근합니다.

### dx/dy 4방향 이동

한 칸에서 상·하·좌·우로 옮겨갈 때, 방향마다 `if`를 네 번 쓰지 않고 **증분 배열**로 묶습니다. [학습_BFS](../problems/programmers/lv2/006_게임_맵_최단거리/학습_BFS.md) 5절의 "4방향 이웃"이 바로 이 관용구입니다.

```python
dx = [-1, 1, 0, 0]   # 상 하 좌 우 (행 변화)
dy = [0, 0, -1, 1]   #            (열 변화)
r, c = 1, 1
grid = [[0] * 3 for _ in range(3)]
for d in range(4):
    nr, nc = r + dx[d], c + dy[d]
    if 0 <= nr < 3 and 0 <= nc < 3:   # 경계 검사
        grid[nr][nc] = 1
print(grid)   # [[0,1,0],[1,0,1],[0,1,0]]  ← 중앙 기준 상하좌우 4칸만 1
```

`dx[d], dy[d]`를 짝으로 더하면 네 방향이 한 루프로 처리됩니다. **8방향**이 필요하면 대각선을 더해 배열을 8칸으로 늘립니다.

```python
dx8 = [-1, -1, -1, 0, 0, 1, 1, 1]
dy8 = [-1,  0,  1,-1, 1,-1, 0, 1]   # 자기 자신(0,0)만 빼고 둘레 8칸
```

### 경계 검사는 이동 "직전"에

`nr, nc`를 만든 **직후**, 격자를 건드리기 **전에** `0 <= nr < 행수 and 0 <= nc < 열수`로 판을 벗어났는지 확인합니다. 이 검사를 빠뜨리면 음수 인덱스로 반대쪽 끝을 읽거나(파이썬은 `grid[-1]`이 에러가 아니라 마지막 행!) 범위 초과로 터집니다(5절 단골 함정).

### in-place vs 새 배열

격자를 갱신할 때 **원본을 그 자리에서 고칠지**, **새 배열을 만들지** 선택해야 합니다.

```python
board = [[1, 2], [3, 4]]
doubled = [[v * 2 for v in row] for row in board]   # 새 배열
print(board)     # [[1, 2], [3, 4]]   ← 원본 그대로
print(doubled)   # [[2, 4], [6, 8]]
```

이 선택은 [학습_정렬](학습_정렬.md) 2절의 `sorted`(새 리스트) vs `sort`(in-place) 대비와 같은 갈림길입니다.
"한 스텝에서 모든 칸이 **동시에** 바뀌어야 하는" 규칙이면 **반드시 새 배열**에 써야 합니다(5절에서 이유를 봅니다). ⚠️ 참고로 `[[0]*3]*3`처럼 곱으로 2차원을 만들면 **모든 행이 같은 리스트**를 가리켜 한 칸만 바꿔도 전 행이 바뀝니다. 위 예처럼 `[[0]*3 for _ in range(3)]`로 만들어야 안전합니다.

## 3. 방향 전환·회전 — 배열 순환과 90도 돌리기

### 방향 배열 순환

"오른쪽으로 90도 돈다", "왼쪽으로 돈다" 같은 규칙은 **방향을 시계 순서로 배열에 늘어놓고 인덱스를 `% 4`로 돌립니다.**

```python
DIRS = ["북", "동", "남", "서"]   # 시계 방향 순서로 나열
d = 0
d = (d + 1) % 4   # +1 = 시계로 한 번
print(DIRS[d])    # 동
d = (d - 1) % 4   # -1 = 반시계로 한 번 → 다시 북
print(DIRS[d])    # 북
```

배열을 **시계 순서로** 두는 것이 핵심입니다. 그러면 `+1`이 시계 회전, `-1`이 반시계 회전으로 딱 대응합니다. `% 4` 덕분에 서(3)에서 시계로 한 번 더 돌면 북(0)으로 감기고, 북(0)에서 반시계로 돌면 `(0-1)%4 == 3` 서로 감깁니다(파이썬 `%`는 음수에도 양수 나머지를 줍니다).

이때 dx/dy 배열도 **같은 시계 순서로** 맞춰 두면, `방향 인덱스 d` 하나로 회전과 이동을 동시에 처리할 수 있습니다.

### 격자 90도 회전 — 전치 + 뒤집기

격자 판 자체를 90도 돌리는 규칙은 **전치(transpose) → 각 행 뒤집기**로 만듭니다.

```python
m = [[1, 2, 3],
     [4, 5, 6]]
transposed = [list(row) for row in zip(*m)]   # 전치: 행↔열 뒤바꿈
rotated = [row[::-1] for row in transposed]    # 각 행 뒤집기 → 시계 90도
print(rotated)   # [[4, 1], [5, 2], [6, 3]]
```

- `zip(*m)` — 언패킹으로 행들을 나란히 묶어 **전치**합니다(2×3 → 3×2).
- 전치 후 **각 행을 뒤집으면 시계 방향** 90도, **먼저 뒤집고 전치하면 반시계** 방향이 됩니다. 순서를 바꾸면 회전 방향이 반대가 되니 주의합니다(5절 함정).

슬라이싱 뒤집기 `[::-1]`는 문자열_구현 2절에서 문자열에 썼던 것과 **같은 관용구**를, 이번엔 행 리스트에 적용한 것입니다.

## 4. 시간·상태 시뮬레이션 — 입/출력 쌍 매칭과 누적

격자가 없어도 시뮬레이션은 나옵니다. "들어옴/나감 기록을 순서대로 처리하며 시간을 누적"하는 유형이 대표적입니다.

```python
records = [("IN", 10), ("OUT", 35), ("IN", 40), ("OUT", 100)]
enter = None
total = 0
for kind, t in records:
    if kind == "IN":
        enter = t                 # 들어온 시각을 기억
    else:
        total += t - enter        # 나갈 때 머문 시간을 누적
print(total)   # (35-10)+(100-40) = 85
```

핵심 감각은 **"상태 변수(`enter`)에 직전 사건을 기억해 두었다가, 짝이 되는 사건에서 정산한다"**는 것입니다. 들어온 시각을 붙들고 있다가 나갈 때 빼서 더하는 이 패턴은 시간·구간 문제에서 반복됩니다.

### 조건이 많으면 "규칙을 번호 목록으로" 분해

시간·요금 계산류는 규칙이 5개, 10개씩 흩어져 나옵니다(예: 기본 시간·기본 요금·단위 시간·단위 요금·올림 처리·미출력 항목의 마감 시각 등). 이럴 때는 문자열_구현 3절의 **분해 → 검증 → 옮기기 → 점검** 절차를 그대로 씁니다.

- **규칙을 번호 매긴 목록으로** 눈에 보이게 적는다(①②③…).
- 지문의 입출력 예시를 그 목록에 대입해 "내 규칙이 이 예시를 재현하는가" 검증한다.
- 확정된 규칙만 코드로 옮긴다(새 판단을 옮기는 단계에서 하지 않는다).

특히 시간류의 함정은 **"기록에 안 나온 상태"** 입니다. 예를 들어 "끝까지 나가지 않은 것은 마감 시각에 나간 것으로 친다" 같은 규칙은 예시에 안 드러날 수 있으니, 목록으로 뽑아 두고 직접 시험해야 합니다.

> **연결:** 규칙 분해의 상세 절차는 [학습_문자열_구현](학습_문자열_구현.md) 3절에 있습니다. 시뮬레이션에서는 거기에 더해 **"스텝의 순서"와 "누적 상태"**까지 목록에 포함시키는 것이 다른 점입니다.

## 5. 자주 나오는 함정

시뮬레이션에서 반복적으로 사람을 걸려 넘어지게 하는 지점들입니다. 문자열_구현 4절의 체크리스트(off-by-one·빈 입력·형 불일치)에 더해, **격자·상태 고유의 함정**을 정리합니다.

| 함정 | 무엇이 문제인가 | 점검 방법 |
|---|---|---|
| **(행,열) vs (x,y) 혼동** | 수학의 `(x, y)`는 가로·세로지만, 격자 `grid[r][c]`는 **세로(행)·가로(열)** 순. 뒤바꾸면 판이 90도 어긋남 | 한 축을 정하고 문서 전체에서 통일. 3×2 같은 **비정사각** 격자로 시험 |
| **경계 off-by-one** | `0 <= nr < 행수` 에서 `<=`를 `<`로, `<`를 `<=`로 쓰면 한 줄이 새거나 넘침 | 크기 1·2짜리 작은 격자에서 네 귀퉁이를 손으로 대조 |
| **음수 인덱스 통과** | `grid[-1]`이 에러가 아니라 **마지막 행**이라, 경계 검사를 빠뜨리면 조용히 반대쪽을 읽음 | 경계 검사를 이동 **직후·접근 직전**에 두었는지 확인 |
| **회전 방향 부호** | 전치+뒤집기 순서, `(d±1)%4`의 부호를 반대로 쓰면 시계/반시계가 뒤집힘 | 비대칭 도형(예: `[[1,2,3],[4,5,6]]`)으로 실제 방향 확인 |
| **동시 갱신 오염** | 한 스텝은 **동시에** 일어나야 하는데 in-place로 순차 갱신하면, 방금 바꾼 값을 다시 읽어 번짐 | 이전 상태를 따로 읽고 **새 배열**에 쓴다(아래) |

### 동시 갱신 오염 — 가장 미묘한 함정

"모든 칸이 **동시에** 규칙에 따라 바뀐다"(생명게임·번짐·동시 이동 등)는 규칙을, 한 배열을 제자리에서 고치며 순차로 처리하면 **방금 바꾼 값을 뒤 칸이 다시 읽어** 오염됩니다.

```python
line = [1, 0, 0, 0]

seq = line[:]                    # in-place로 순차 갱신 (틀림)
for i in range(1, len(seq)):
    if seq[i-1] == 1:            # 방금 내가 바꾼 값을 다시 읽음
        seq[i] = 1
print(seq)                       # [1, 1, 1, 1]  ← 끝까지 번져 오염

nxt = line[:]                    # 이전 상태(line)만 읽고 새 배열(nxt)에 씀 (맞음)
for i in range(1, len(line)):
    if line[i-1] == 1:
        nxt[i] = 1
print(nxt)                       # [1, 1, 0, 0]  ← 한 칸만 번짐
```

규칙이 `1` 옆칸을 `1`로 바꾸는 것뿐인데, 순차 갱신은 새로 켜진 칸을 **같은 스텝 안에서** 또 읽어 도미노처럼 전부 번집니다. 반면 "이전 상태만 읽고 결과는 새 배열에 쓴다"는 방식은 한 스텝의 동시성을 지켜 한 칸만 켜집니다.

> **핵심:** "한 스텝은 동시에 일어난다"는 규칙이 보이면, 읽는 배열과 쓰는 배열을 **분리**하세요(2절 in-place vs 새 배열). 반대로 "차례로 하나씩 옮긴다"가 규칙이면 in-place가 맞습니다 — **규칙이 요구하는 갱신 방식**을 먼저 판정하는 것이 요령입니다.

## 6. 자기 점검 체크리스트 (문서 닫기 전 스스로 답해보기)

1. 시뮬레이션 문제의 공통 뼈대(상태 초기화 → 반복 갱신 → 멈춤 → 결과)를 말로 설명하고, 이것이 정적 구현과 무엇이 다른지 답해 보라. (1절)
2. `dx/dy` 4방향 관용구에서 경계 검사는 **어느 시점에** 넣어야 하며, 빠뜨리면 파이썬 격자에서 왜 에러 없이 조용히 틀리는가? (2절·5절 음수 인덱스)
3. 방향 배열을 **시계 순서**로 두면 `+1`/`-1`이 각각 무엇이 되는가? `(0 - 1) % 4`는 왜 `3`인가? (3절)
4. 격자를 시계 90도로 돌리려면 전치와 뒤집기를 **어느 순서**로 하는가? 순서를 바꾸면 무엇이 달라지는가? (3절·5절)
5. "한 스텝에서 모든 칸이 동시에 바뀐다"는 규칙을 in-place로 처리하면 왜 오염되는가? 이를 막으려면 무엇과 무엇을 분리해야 하는가? (5절)
