# 학습: 힙 (heapq·우선순위 큐)

> 관련 문서: [학습_정렬](학습_정렬.md) · [학습_스택_큐](학습_스택_큐.md) · [학습_그리디](학습_그리디.md) · [학습_BFS](../problems/programmers/lv2/006_게임_맵_최단거리/학습_BFS.md)

스택·큐로 "마지막 것/처음 것"을 O(1)에 꺼내 왔습니다. 그런데 **"항상 가장 작은(또는 큰) 것"** 을 꺼내야 하면 어떻게 할까요?
이 문서에서 **힙(heap)** 을 정리합니다. 힙은 "매번 최솟값(또는 최댓값)을 빠르게 꺼내는" 자료구조입니다.
예제는 전부 중립 소재(숫자·알파벳)로 만들었고, 아래 모든 출력값은 실제로 실행해 검증한 값입니다.

---

## 1. 힙이란 무엇인가 — "매번 최솟값을 빠르게 꺼내는 통"

힙은 **넣고 빼는 사이에도 항상 "가장 작은(또는 큰) 원소"를 O(log N)에 꺼낼 수 있게** 유지되는 자료구조입니다.
스택이 "마지막 것", 큐가 "처음 것"을 꺼내 줬다면, 힙은 **"제일 작은(또는 큰) 것"** 을 꺼내 줍니다. 이걸 **우선순위 큐**라고도 부릅니다 — 넣은 순서가 아니라 **값의 우선순위 순**으로 나오는 큐라는 뜻입니다.

### 우리가 겪은 문제 — "매번 max()로 전체를 훑기"

최근 프로세스류 문제에서, "남은 것 중 가장 큰(우선순위 높은) 것을 골라 처리"하려고 매 반복마다 `max()`로 **전체를 다시 훑은** 적이 있습니다. 이게 왜 느렸을까요?

- 원소가 N개일 때 `max()`는 한 번에 **O(N)**. 이걸 원소 수만큼(N번) 반복하면 전체 **O(N²)** 입니다.
- N이 10만이면 100억 번 — 시간 초과입니다.

힙은 바로 이 "**매번 최소/최대 꺼내기**"를 O(N)에서 **O(log N)** 으로 바꿔 줍니다. 전체를 다시 훑는 대신, 힙이 꼭대기에 최솟값을 **미리 올려놓고 유지**하기 때문입니다.

| 방법 | "최소/최대 하나 꺼내기" | N번 반복하면 |
|---|---|---|
| 매번 `max()`/`min()` 전체 스캔 | O(N) | **O(N²)** ⚠️ |
| 힙 (heappop) | **O(log N)** ✅ | O(N log N) |

> **한 줄 정리:** "남은 것 중 최소/최대를 반복해서 꺼내야 하는데, 매번 `max()`로 전체를 훑고 있다"면 그게 힙 신호입니다. 힙은 그 한 번의 꺼내기를 **O(N) → O(log N)** 으로 낮춥니다.

## 2. 파이썬 `heapq` 기초 — push·pop·heapify

파이썬은 힙 전용 클래스를 따로 두지 않습니다. **평범한 `list`를 `heapq` 함수들로 다루면** 그 리스트가 곧 힙이 됩니다.
그리고 **기본이 최소 힙(min-heap)** 입니다 — 꺼내면 항상 **가장 작은 값**이 나옵니다.

```python
import heapq

heap = []
heapq.heappush(heap, 5)          # 넣기
heapq.heappush(heap, 1)
heapq.heappush(heap, 3)
print(heap[0])                   # 1   ← 최솟값 훔쳐보기(peek), O(1)
print(heapq.heappop(heap))       # 1   ← 최솟값 꺼내기
print(heapq.heappop(heap))       # 3   ← 그다음 최솟값
```

- `heappush(heap, x)` — 원소를 넣는다. **O(log N)**
- `heappop(heap)` — **최솟값**을 꺼내 돌려준다. **O(log N)**
- `heap[0]` — 꺼내지 않고 **최솟값만 확인**(peek). **O(1)**

### `heapify` — 리스트를 한 번에 힙으로

이미 원소가 든 리스트가 있으면, 하나씩 push하는 대신 **`heapify`로 통째로** 힙으로 만들 수 있습니다. 이게 더 빠릅니다(O(N)).

```python
import heapq

nums = [5, 1, 3, 2, 4]
heapq.heapify(nums)              # 리스트를 제자리에서 힙으로 (O(N))
print(nums[0])                   # 1   ← 최솟값이 항상 맨 앞
print(heapq.heappop(nums))       # 1
```

### ⚠️ "힙 = 정렬된 리스트"가 아니다

`heapify` 후 리스트를 그대로 출력하면 **정렬돼 보이지 않습니다.**

```python
import heapq

nums = [5, 1, 3, 2, 4]
heapq.heapify(nums)
print(nums)                      # [1, 2, 3, 5, 4]   ← 정렬 아님!
```

힙이 보장하는 건 **"맨 앞(`[0]`)이 최솟값"** 이라는 것뿐, 나머지 자리의 순서는 아닙니다. 정렬된 전체 순서가 필요하면 `sorted()`를 써야 합니다. **"꺼낼 때마다 최솟값이 나온다"** 와 "리스트가 정렬돼 있다"는 다른 이야기입니다.

| 연산 | 시간복잡도 |
|---|---|
| `heappush` (넣기) | O(log N) |
| `heappop` (최솟값 꺼내기) | O(log N) |
| `heap[0]` (최솟값 확인) | **O(1)** |
| `heapify` (리스트 → 힙) | O(N) |

> **한 줄 정리:** `heapq`는 **평범한 리스트**를 힙으로 다루는 함수 모음이고, **기본은 최소 힙**입니다. `heappush`/`heappop`은 O(log N), `heap[0]`은 O(1). 단, 힙 리스트 자체는 정렬 상태가 아닙니다.

## 3. 최대 힙 만들기 — 파이썬엔 최소 힙만 있다

`heapq`는 **최소 힙만** 제공합니다. "가장 **큰** 것부터" 꺼내고 싶으면 두 가지 관용구를 씁니다.

### ⓐ 부호 반전 — `-x`로 넣고 `-`로 되돌리기

가장 흔한 방법입니다. **넣을 때 부호를 뒤집어** 넣으면, 최소 힙이 "가장 작은 음수"(= 원래 가장 큰 값)를 먼저 꺼내 줍니다. **꺼낼 때 다시 `-`로 되돌립니다.**

```python
import heapq

maxh = []
for x in [5, 1, 3]:
    heapq.heappush(maxh, -x)     # 부호 뒤집어 넣기
print(-heapq.heappop(maxh))      # 5   ← 꺼낼 때 다시 뒤집기
print(-heapq.heappop(maxh))      # 3
```

`5`를 `-5`로, `1`을 `-1`로 넣으면 최소 힙엔 `-5`가 가장 작으니 먼저 나오고, `-`로 되돌리면 `5`가 됩니다. **"넣을 때 `-`, 꺼낼 때 `-`"** 한 쌍만 기억하면 됩니다. ([학습_정렬](학습_정렬.md) 3절의 "숫자 내림차순은 `-x`"와 같은 발상입니다.)

### ⓑ 튜플로 우선순위 지정

원소에 **(우선순위, 값)** 튜플을 넣으면, 힙은 **튜플 앞 원소부터** 비교해 정렬합니다([학습_정렬](학습_정렬.md) 3절 "튜플 key"와 같은 규칙). 우선순위와 실제 데이터를 분리하고 싶을 때 유용합니다.

```python
import heapq

th = []
heapq.heappush(th, (2, "b"))
heapq.heappush(th, (1, "a"))
heapq.heappush(th, (3, "c"))
print(heapq.heappop(th))         # (1, 'a')   ← 우선순위(첫 원소) 가장 작은 것
```

첫 원소(`1`, `2`, `3`)가 우선순위라, `(1, "a")`가 먼저 나옵니다. "최대 우선순위부터" 원하면 여기서도 **우선순위 자리에 `-`를 붙이면**(`(-2, "b")` …) 됩니다.

> **한 줄 정리:** 파이썬엔 **최소 힙만** 있습니다. 최대 힙이 필요하면 **`-x`로 부호를 뒤집어** 넣고 꺼낼 때 되돌리거나, **`(우선순위, 값)` 튜플**로 우선순위를 명시합니다.

## 4. 언제 힙을 쓰나 — 정렬과의 결정적 차이

힙을 떠올려야 하는 신호는 하나로 요약됩니다.

> **"매번 최소/최대를 반복해서 꺼내는데, 그 사이에 새 값이 계속 들어온다."**

"그 사이에 새 값이 들어온다"가 정렬과 힙을 가르는 핵심입니다.

### 정렬로 충분한 경우 — 값이 고정돼 있다

원소가 **처음에 다 주어지고 중간에 안 바뀌면**, 그냥 한 번 정렬하면 끝입니다. `sorted()` O(N log N) 한 방이면 작은 것부터 순서대로 다 꺼낼 수 있습니다([학습_정렬](학습_정렬.md) 참고).

```python
import heapq

data = [5, 1, 3, 2, 4]
heapq.heapify(data)
out = []
while data:
    out.append(heapq.heappop(data))
print(out)                       # [1, 2, 3, 4, 5]
```

위처럼 "넣고 다 꺼내기"만 하면 결과는 정렬과 똑같습니다. 이럴 거면 굳이 힙이 필요 없습니다.

### 힙이 꼭 필요한 경우 — 꺼내는 도중에 새 값이 들어온다

진짜 힙이 빛나는 건 **"최소 하나 꺼내고 → 뭔가 계산해 → 그 결과를 다시 넣고 → 또 최소를 꺼내고 …"** 처럼 **동적으로 계속 갱신**될 때입니다. 정렬은 이 상황에 무력합니다 — 새 값이 들어올 때마다 **다시 정렬(O(N log N))** 해야 하니까요.

| | 정렬 | 힙 |
|---|---|---|
| 언제 | 원소가 **처음에 다 주어지고 안 바뀜** | 꺼내는 **도중에 새 값이 계속 들어옴** |
| 무엇을 | **전체 순서**를 한 번에 확정 | **최소/최대 하나**만 그때그때 |
| 새 값 추가 | 다시 정렬 O(N log N) | `heappush` O(log N) ✅ |
| 대표 상황 | 목록 줄 세우기 | 우선순위가 바뀌며 하나씩 처리 |

- **정렬**: "한 번에 다 줄 세워 놓고" 그 위에서 작업. 정적입니다.
- **힙**: "지금 필요한 최소/최대 하나"만 꺼내고, **새 값이 들어와도 O(log N)에 자리를 잡아** 줍니다. 동적입니다.

그래서 1절의 프로세스류 문제처럼 "가장 우선순위 높은 것을 꺼내 처리했더니 **새 작업이 생겨 다시 넣어야** 하는" 구조는 정렬이 아니라 **힙**입니다. 매번 다시 정렬하면 느리고, 매번 `max()`로 훑으면 O(N²)이니까요.

> **핵심:** "**최소/최대를 반복해 꺼내는데 그 사이 새 값이 계속 들어온다**"가 보이면 힙입니다. 값이 고정이면 정렬 한 방으로 충분하고, **동적으로 갱신되면** 힙이 정답입니다. 정렬은 "한 번에 전부", 힙은 "그때그때 최소만".

## 5. 자기 점검 체크리스트 (문서 닫기 전 스스로 답해보기)

1. "매 반복마다 `max()`로 전체를 훑어 원소를 하나씩 꺼낸다"가 왜 O(N²)이 되는가? 힙을 쓰면 그 한 번의 꺼내기가 몇으로 바뀌는가?
2. 파이썬 `heapq`는 기본이 최소 힙인가 최대 힙인가? `heappush`·`heappop`·`heap[0]`의 시간복잡도는 각각 얼마인가?
3. `heapify(nums)` 후 `nums`를 출력하면 왜 정렬된 것처럼 안 보이는가? 힙이 보장하는 것은 정확히 무엇 하나인가?
4. 최대 힙이 필요할 때 "부호 반전" 관용구는 넣을 때와 꺼낼 때 각각 무엇을 하는가? 튜플 `(우선순위, 값)`은 힙이 무엇을 기준으로 비교하는가?
5. "원소가 처음에 다 주어지고 안 바뀌는" 경우와 "꺼내는 도중에 새 값이 계속 들어오는" 경우 중, 정렬로 충분한 쪽과 힙이 꼭 필요한 쪽은 각각 어느 것인가? 왜인가?
