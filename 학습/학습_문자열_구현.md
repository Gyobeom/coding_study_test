# 학습: 문자열·구현

> 관련 문서: [학습_DFS](학습_DFS.md) · [학습_BFS](../problems/programmers/lv2/006_게임_맵_최단거리/학습_BFS.md) · [학습_해시](학습_해시.md)

DFS·BFS·해시가 "**어떤 도구를 쓸지** 알아채는" 승부였다면, **구현 문제**는 결이 다릅니다.
쓸 도구는 대개 뻔합니다(반복문·조건문·문자열 함수). 대신 **지문을 조건 누락 없이 정확히 코드로 옮기는 것** 자체가 승부입니다.
이 문서는 그 정확성을 위한 **문자열 도구함**과 **접근 절차**를 정리합니다. 예제는 전부 중립 소재로 만들었고, 출력값은 실제로 실행해 검증했습니다.

---

## 1. 구현 문제란 무엇인가

구현(implementation) 문제는 **"기발한 알고리즘"이 아니라 "지문 그대로 옮기는 정확성"** 을 봅니다.

- DFS/BFS/해시 문제는 "이건 최단거리니까 BFS다"처럼 **도구를 알아채면** 절반이 풀립니다.
- 구현 문제는 도구가 뻔합니다. 대신 지문에 조건이 **5개, 10개** 흩어져 있고, 그중 **하나라도 빠뜨리면** 틀립니다.

그래서 구현 문제의 어려움은 "떠올리기"가 아니라 **"빠짐없이 옮기기"** 에 있습니다.
지문을 읽으며 "아, 이 조건도 있었지"를 코드에 다 반영했는가 — 여기서 정답이 갈립니다.

> **한 줄 정리:** 구현 문제는 **발상 30% / 꼼꼼함 70%**. "어떻게 풀지"보다 "조건을 다 챙겼는지"가 핵심입니다.

## 2. 파이썬 문자열 도구함

구현 문제에서 반복해 쓰는 문자열 도구들입니다. 하나씩 손에 익혀 두면 지문을 코드로 옮기는 속도가 붙습니다.

### 슬라이싱 — 일부 잘라내기

```python
s = "abcdef"
print(s[0])       # a       ← 첫 글자
print(s[-1])      # f       ← 마지막 글자 (음수 인덱스)
print(s[1:4])     # bcd     ← 1번부터 4번 "직전"까지 (끝은 포함 안 함)
print(s[::-1])    # fedcba  ← 뒤집기 관용구
```

`s[1:4]` 에서 **끝 인덱스 4는 포함되지 않는다**는 점이 off-by-one 실수의 단골 원인입니다(4절).

### `split` / `join` — 쪼개기와 붙이기

```python
line = "김,이,박"
parts = line.split(",")     # 구분자로 쪼개 리스트로
print(parts)                # ['김', '이', '박']
print("-".join(parts))      # 김-이-박    ← 리스트를 구분자로 이어 문자열로
```

`split`은 문자열 → 리스트, `join`은 리스트 → 문자열. **정반대 짝**입니다.

### 정렬 — `sorted` 와 `key` 인자

```python
words = ["banana", "kiwi", "apple"]
print(sorted(words))                        # ['apple', 'banana', 'kiwi']  (사전순)
print(sorted(words, key=len))               # ['kiwi', 'apple', 'banana']  (길이순)
print(sorted(words, key=len, reverse=True)) # ['banana', 'apple', 'kiwi']  (길이 내림차순)
```

`key=`에 "무엇을 기준으로 정렬할지"를 넘깁니다. `key=len`은 "길이를 기준으로". 이게 구현 문제 정렬의 핵심입니다.

### 동점 처리 — 튜플 `key`

"1순위로 A, 같으면 2순위로 B" 같은 규칙은 **튜플**을 key로 돌려주면 됩니다.

```python
students = [("김", 90), ("이", 80), ("박", 90)]
# 점수 내림차순, 같은 점수면 이름 오름차순
print(sorted(students, key=lambda x: (-x[1], x[0])))
# [('김', 90), ('박', 90), ('이', 80)]
```

`(-x[1], x[0])` — 점수는 **내림차순이라 부호를 뒤집고**(`-x[1]`), 동점이면 이름 오름차순(`x[0]`). 튜플은 앞 원소부터 차례로 비교되므로 "1순위 → 2순위" 규칙이 그대로 표현됩니다.

### 형변환 — 숫자 ↔ 문자열 ↔ 리스트

```python
print(int("42") + 1)     # 43       ← 문자열 → 정수
print(str(42) + "!")     # 42!      ← 정수 → 문자열
print(list("abc"))       # ['a', 'b', 'c']   ← 문자열 → 글자 리스트
```

입력이 문자열인데 숫자 계산이 필요하면 `int(...)`, 반대로 숫자를 이어 붙이려면 `str(...)`. 형이 안 맞아 나는 오류의 대부분이 여기서 옵니다.

### f-string — 형식 맞춰 문자열 만들기

```python
name, score = "김", 90
print(f"{name}: {score}점")     # 김: 90점
print(f"{3.14159:.2f}")          # 3.14   ← 소수점 2자리
print(f"{7:03d}")                # 007    ← 3칸, 빈자리는 0으로
```

`f"..."` 안의 `{}` 에 변수나 식을 넣으면 값으로 바뀝니다. `:.2f`(소수 자리), `:03d`(자릿수 채우기) 같은 형식 지정이 출력 규칙이 까다로운 구현 문제에서 유용합니다.

## 3. 구현 문제 접근 절차

구현 문제는 "바로 코딩"이 함정입니다. 조건을 놓치기 쉬우므로 **분해 → 검증 → 옮기기 → 점검** 순서를 지킵니다. (특정 문제 풀이가 아닌 일반론입니다.)

**1단계 — 지문을 조건 목록으로 분해한다.**
지문을 문장 단위로 끊어 "지켜야 할 규칙"을 번호 매긴 목록으로 만듭니다. 예를 들어 어떤 명단 처리 문제라면:
- ① 입력은 이름 문자열의 리스트다
- ② 중복된 이름은 한 번만 센다
- ③ 결과는 사전순으로 정렬해 돌려준다
- ④ 빈 리스트가 들어오면 빈 리스트를 돌려준다

이렇게 **눈에 보이는 목록**으로 만들어야 나중에 "다 챙겼나?"를 대조할 수 있습니다.

**2단계 — 예시 입출력으로 조건을 검증한다.**
지문의 입출력 예시를 1단계 목록에 하나씩 대입해, "내가 뽑은 조건이 이 예시를 정말 설명하는가"를 확인합니다.
예시가 내 조건 목록으로 재현되지 않으면 **조건을 잘못 읽은 것**이니, 코드를 짜기 전에 바로잡습니다.

**3단계 — 조건 목록을 코드로 옮긴다.**
이제 목록의 각 항목을 코드 한 덩어리씩 대응시킵니다. 이 단계에서 **새로운 판단을 하지 않는 것**이 요령입니다 — 1·2단계에서 확정한 조건만 옮깁니다.

**4단계 — 엣지 케이스를 점검한다.**
정상 예시가 통과해도 끝이 아닙니다. 빈 입력·경계값 등(4절 목록)을 스스로 넣어 봅니다. 특히 1단계에서 뽑은 조건 중 **예시에 안 나온 조건**(위 ④ 같은 것)을 직접 시험해야 합니다.

> **핵심:** 구현 문제에서 버그는 대개 "코딩 실수"가 아니라 **"1단계에서 조건을 빠뜨린 것"** 입니다.
> 그래서 코드보다 **조건 목록을 먼저, 눈에 보이게** 만드는 데 시간을 쓰는 편이 결국 빠릅니다.

## 4. 자주 나오는 함정

구현 문제에서 반복적으로 사람을 걸려 넘어지게 하는 지점들입니다. 4단계 점검 때 이 목록을 체크리스트로 쓰세요.

| 함정 | 무엇이 문제인가 | 점검 방법 |
|---|---|---|
| **off-by-one** | `s[1:4]`의 끝 미포함, 범위 `range(n)` vs `range(n+1)` 등 경계 1칸 어긋남 | 길이 1·2짜리 작은 입력으로 손으로 대조 |
| **빈 입력** | 빈 문자열·빈 리스트에서 인덱싱하면 오류(`s[0]`) | `""`, `[]` 를 넣어 본다 |
| **대소문자** | "Apple"과 "apple"을 같게/다르게 봐야 하는지 지문 확인 | `.lower()`로 통일할지 지문에서 판단 |
| **정렬 안정성** | 같은 key끼리는 **원래 순서가 보존**된다(파이썬 `sorted`는 안정) | 동점 순서가 지문 요구와 맞는지 확인 |
| **동점 처리** | 1순위가 같을 때 2순위 규칙을 지문이 정해 두는 경우가 많음 | 튜플 key로 2순위까지 명시 (2절) |
| **형(type) 불일치** | 문자열 "42"와 정수 42를 섞어 비교/연산 | 입력 형을 확인하고 `int`/`str`로 맞춤 |

### 대소문자·빈 입력 예시

```python
print("Hello".lower())    # hello   ← 비교 전 소문자로 통일하고 싶을 때
print("Hello".upper())    # HELLO

empty = ""
print(len(empty))         # 0       ← 빈 입력은 길이 0
print(empty[:1])          # (빈 문자열 출력, 에러 안 남)
```

`empty[0]` 은 `IndexError`로 터지지만, **슬라이싱 `empty[:1]` 은 안전하게 빈 문자열**을 돌려줍니다. 빈 입력을 다룰 때 인덱싱 대신 슬라이싱이 더 안전한 경우가 있습니다.

### 정렬 안정성이 왜 중요한가

파이썬 `sorted`는 **안정 정렬**입니다 — key가 같은 원소끼리는 **입력에 있던 순서가 그대로** 유지됩니다.

```python
students = [("김", 90), ("이", 80), ("박", 90)]
# 점수만 기준으로 정렬 (이름은 key에 안 넣음)
print(sorted(students, key=lambda x: -x[1]))
# [('김', 90), ('박', 90), ('이', 80)]  ← 90점끼리는 입력 순서(김→박) 유지
```

동점인 김·박이 입력 순서대로 나온 것은 우연이 아니라 **안정 정렬의 보장**입니다. 지문이 "동점이면 먼저 들어온 순서" 라면 이 성질만으로 충분하고, "동점이면 이름순"이라면 2절처럼 key에 2순위를 명시해야 합니다.

## 5. 자기 점검 체크리스트 (문서 닫기 전 스스로 답해보기)

1. `s[1:4]` 는 몇 글자를 돌려주며, 어느 인덱스가 **포함되지 않는가**? off-by-one은 왜 여기서 자주 생기는가?
2. "점수 내림차순, 같으면 이름 오름차순"을 하나의 `key`로 어떻게 표현하는가? (2절 튜플 key)
3. 구현 문제에서 버그가 "코딩 실수"보다 "조건 누락"에서 더 자주 나는 이유는? 이를 막으려면 코드를 짜기 전에 무엇을 해야 하는가? (3절)
4. 빈 문자열 `""` 에서 `s[0]` 과 `s[:1]` 은 각각 어떻게 되는가? 왜 다른가?
5. 파이썬 `sorted`가 "안정 정렬"이라는 것은 무슨 뜻이며, 동점 처리에서 이 성질을 언제 믿고 언제 key에 2순위를 명시해야 하는가?
