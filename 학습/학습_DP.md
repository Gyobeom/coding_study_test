# 학습: DP (동적 계획법)

> 관련 문서: [학습_DFS](학습_DFS.md) · [학습_그리디](학습_그리디.md) · [학습_해시](학습_해시.md) · [학습_BFS](../problems/programmers/lv2/006_게임_맵_최단거리/학습_BFS.md)

지금까지 DFS로 **모든 경우를 빠짐없이** 훑고, 그리디로 **매 순간 한 수만** 집었습니다.
이 문서에서 **DP(동적 계획법, Dynamic Programming)** 를 정리합니다. DP는 그 사이에 있습니다 — 모든 경우를 보되, **한 번 푼 작은 문제의 답을 저장해 다시 계산하지 않는** 방식입니다.
예제는 전부 중립 소재(피보나치·계단)로 만들었고, 아래 모든 출력값은 실제로 실행해 검증한 값입니다.

---

## 1. DP란 무엇인가 — "작은 문제의 답을 저장해 큰 문제에 재활용"

DP는 **큰 문제를 작은 부분문제로 쪼갠 뒤, 작은 문제의 답을 한 번 구해 저장해 두고, 그 답을 큰 문제에 재활용**하는 방식입니다.

핵심은 "**한 번 푼 건 두 번 안 푼다**"입니다. 같은 작은 문제가 여러 번 필요해도, 처음 한 번만 계산하고 나머지는 저장해 둔 값을 꺼내 씁니다.

### 완전탐색(DFS)과의 대비 — 낭비를 없앤다

DFS 완전탐색은 "가능한 경우를 전부 열어 본다"였습니다([학습_DFS](학습_DFS.md) 3절). 그런데 갈래를 뻗다 보면 **똑같은 부분문제를 몇 번이고 다시 계산**하게 될 때가 있습니다. DP는 바로 그 **중복 계산을 없앤** 완전탐색입니다.

| | 완전탐색 (DFS) | DP |
|---|---|---|
| 한 마디로 | 모든 경우를 **매번 새로** 계산 | 모든 경우를 보되 **한 번 푼 건 저장해 재활용** |
| 같은 부분문제 | 마주칠 때마다 **또 계산** | 처음 한 번만 계산, 이후 **꺼내 씀** |
| 비용 | 갈래가 겹치면 지수($2^n$)로 폭발 | 부분문제 개수만큼만 → 대개 다항식 |

### 그리디와의 대비 — 한 수 vs 모든 조합

그리디도 빠르지만 태도가 다릅니다([학습_그리디](학습_그리디.md) 1절). 그리디는 **지금 최선 한 수**만 집고 되돌아보지 않습니다. DP는 **부분문제로 나눠 가능한 조합을 다 따진 뒤** 그중 최적을 고릅니다.

| | 그리디 | DP |
|---|---|---|
| 무엇을 보나 | 매 순간 **지역 최적 한 수** | 부분문제들의 **모든 조합**에서 최적 |
| 되돌아봄 | 없음 (한 번 고르면 끝) | 부분문제 답을 다 쥐고 그중 최적 선택 |
| 위험 | 전략이 틀리면 "그럴듯한 오답" | 점화식이 맞으면 항상 정답 |

> **한 줄 정리:** DP는 "완전탐색인데 같은 계산을 반복하지 않는 것"입니다. 그리디가 한 수만 보고 달린다면, DP는 **작은 문제부터 차곡차곡 답을 쌓아** 큰 문제의 정답을 만듭니다.

## 2. DP가 성립하는 두 조건

그리디에 "지역 최적의 누적 = 전역 최적"이라는 성립 조건이 있었듯([학습_그리디](학습_그리디.md) 2절), DP에도 두 조건이 있습니다. **둘 다** 만족해야 DP가 의미 있습니다.

### ① 최적 부분구조 — "부분의 최적으로 전체의 최적을 만든다"

큰 문제의 최적해가 **작은 부분문제들의 최적해로 조립**되어야 합니다. "n칸 계단을 오르는 방법 수"가 "(n-1)칸까지의 방법 수"와 "(n-2)칸까지의 방법 수"의 합으로 정해지는 것이 그 예입니다. 부분의 답을 알면 전체의 답이 나옵니다.

### ② 중복 부분문제 — "같은 작은 문제가 여러 번 나온다"

같은 부분문제가 **반복해서 등장**해야 저장이 이득입니다. 안 겹치면 저장할 게 없어 그냥 완전탐색입니다.

피보나치 `fib(n) = fib(n-1) + fib(n-2)` 를 순수 재귀로 펼치면 같은 값이 몇 번이고 다시 계산됩니다.

```
              fib(5)
            /        \
        fib(4)        fib(3)
        /    \        /    \
    fib(3)  fib(2)  fib(2) fib(1)
    /   \
 fib(2) fib(1)      ← fib(2), fib(3)이 여러 번 반복 등장!
```

`fib(3)`은 두 번, `fib(2)`는 세 번 계산됩니다. n이 커지면 이 중복이 지수로 폭발합니다. 실제로 `fib(10)`을 순수 재귀로 구하면 함수 호출이 **177번** 일어납니다(값은 55). 이 겹침이 바로 DP로 없앨 낭비입니다.

> **한 줄 정리:** ① 부분문제의 최적으로 전체 최적을 조립할 수 있고(최적 부분구조), ② 그 부분문제가 여러 번 겹칠 때(중복 부분문제) DP가 빛납니다. 겹침이 없으면 저장할 이유가 없습니다.

## 3. 두 가지 구현 방식 — Top-down과 Bottom-up

같은 점화식을 **두 방향**으로 채울 수 있습니다. 큰 문제에서 내려가며 캐시하거나(Top-down), 작은 문제부터 쌓아 올리거나(Bottom-up)입니다.

### ⓐ Top-down (재귀 + 메모이제이션)

여러분이 **계단 오르기를 처음 재귀 DFS로 풀 때 스쳐 지나간 "메모이제이션"** 이 바로 이것입니다([학습_DFS](학습_DFS.md) 2절의 반환형 재귀에 **캐시 한 겹**을 씌운 것). 완전탐색 재귀는 그대로 두고, "이미 구한 값이면 다시 계산 말고 꺼내 쓴다"만 추가합니다.

```python
memo = {}
def fib_top(n):
    if n <= 1:
        return n
    if n in memo:          # 이미 구했으면 저장된 값을 즉시 반환
        return memo[n]
    memo[n] = fib_top(n - 1) + fib_top(n - 2)
    return memo[n]
print(fib_top(10))   # 55
```

`if n in memo: return memo[n]` 이 한 줄이 핵심입니다. 이게 없으면 2절의 순수 재귀(177번 호출)이고, 있으면 각 `n`을 **딱 한 번씩만** 계산합니다.

### ⓑ Bottom-up (반복 + 테이블)

재귀 대신 **작은 것부터 순서대로** 배열(테이블)을 채웁니다. `dp[0]`, `dp[1]`을 정해 두고 `dp[2]`, `dp[3]`... 을 앞의 값으로 계산해 올라갑니다.

```python
def fib_bottom(n):
    if n <= 1:
        return n
    dp = [0] * (n + 1)
    dp[1] = 1
    for i in range(2, n + 1):
        dp[i] = dp[i - 1] + dp[i - 2]   # 이미 채운 앞 칸을 꺼내 씀
    return dp[n]
print(fib_bottom(10))   # 55
```

`dp[i]`를 계산할 때 `dp[i-1]`, `dp[i-2]`는 **이미 채워져 있으므로** 재계산이 없습니다. 재귀 스택도 필요 없습니다.

### 둘의 관계

| | Top-down | Bottom-up |
|---|---|---|
| 방향 | 큰 문제 → 작은 문제 (재귀로 내려감) | 작은 문제 → 큰 문제 (반복으로 쌓음) |
| 저장 | `memo` 딕셔너리에 필요할 때만 | `dp` 배열을 처음부터 순서대로 |
| 장점 | 완전탐색 재귀에 캐시만 얹으면 됨 (직관적) | 스택 깊이 걱정 없음, 대개 더 빠름 |

> **정리:** 같은 점화식을 **위에서 캐시하며 내려오느냐(Top-down), 아래서 채우며 올라가느냐(Bottom-up)** 의 차이일 뿐입니다. 둘 다 "한 번 푼 부분문제를 재활용"이라는 목적은 같습니다. 재귀가 편하면 Top-down으로 시작하고, 익숙해지면 Bottom-up 테이블로 정리하는 흐름을 권합니다.

## 4. 점화식 세우기 — DP의 진짜 승부처

해시의 승부가 "무엇을 키로 삼을까"였다면([학습_해시](학습_해시.md) 3절 ⓒ), DP의 승부는 **"dp[i]를 무엇으로 정의할까"** 입니다. 정의만 잘 잡으면 점화식은 따라옵니다. 순서는 항상 셋입니다.

> **① 정의 → ② 점화 관계 → ③ 초기값(base case)**

중립 예제로 도출해 봅니다. **한 번에 1칸 또는 2칸** 오를 수 있을 때, n칸 계단을 오르는 **방법의 수**를 구합니다.

### ① 정의 — dp[i]가 무엇인지 한 문장으로

> `dp[i]` = **i번째 칸까지 오르는 서로 다른 방법의 수**

이 한 문장이 가장 중요합니다. 정의가 모호하면 점화식도 세워지지 않습니다.

### ② 점화 관계 — dp[i]를 더 작은 dp로 표현

i번째 칸에 **마지막으로 도착하는 방법**을 따집니다. 직전 걸음이 1칸이었다면 (i-1)에서 왔고, 2칸이었다면 (i-2)에서 왔습니다. 두 경우가 전부이고 서로 겹치지 않으므로:

> `dp[i] = dp[i-1] + dp[i-2]`

"(i-1)까지 온 모든 방법" + "(i-2)까지 온 모든 방법"이 곧 "i까지 온 방법"입니다. 이것이 2절 ①의 최적 부분구조입니다.

### ③ 초기값 — 점화식이 딛고 설 바닥

`dp[i-1]`, `dp[i-2]`를 쓰려면 맨 아래 몇 칸은 **직접 정해** 둬야 합니다.

> `dp[0] = 1` (아무 데도 안 오른 "제자리"도 한 가지 방법) · `dp[1] = 1` (1칸은 1칸 오르기 한 가지)

세 조각을 코드로 옮기면:

```python
def climb(n):
    if n <= 1:
        return 1
    dp = [0] * (n + 1)
    dp[0] = dp[1] = 1            # ③ 초기값
    for i in range(2, n + 1):
        dp[i] = dp[i - 1] + dp[i - 2]   # ② 점화 관계
    return dp[n]                 # ① dp[n] = n칸까지의 방법 수
print([climb(i) for i in range(6)])   # [1, 1, 2, 3, 5, 8]
```

`dp[2]=2, dp[3]=3, dp[4]=5, dp[5]=8`. 계단 방법 수가 피보나치와 같은 점화식이라는 게 눈에 보입니다.

> **정리:** 막히면 코드부터 짜지 말고 **① dp[i]를 한 문장으로 정의**하세요. 정의가 서면 "i에 마지막으로 도달하는 경우"를 따져 ② 점화식이 나오고, 그 식이 딛을 ③ 바닥값을 정하면 끝입니다. **정의 → 점화 → 초기값**, 이 순서를 습관으로 만드세요.

## 5. DP 문제를 알아보는 신호

지문에서 아래 단서가 보이면 DP를 먼저 떠올립니다. 그리디의 신호("정렬해 앞에서부터")나 해시의 신호("몇 개·빈도")와 구분되는 감각입니다.

| 지문의 신호 | 왜 DP인가 |
|---|---|
| "**방법의 수**", "**경우의 수**를 구하라" | 부분문제의 경우 수를 합쳐 올라감 (계단·피보나치형) |
| "**최대/최소 비용**", "최댓값·최솟값을 구하라" | 부분문제의 최적을 조합 (최적 부분구조) |
| "**이전 선택이 다음에 영향**을 준다" | i의 답이 i-1, i-2에 의존 → 점화식 |
| 완전탐색이면 **지수 시간**인데 부분문제가 겹침 | 중복 부분문제 → 저장으로 다항식화 |

### 그리디와 헷갈릴 때

"최대/최소"는 그리디에도 나옵니다. 갈림은 **되돌아봄이 필요한가**입니다.

- 매 순간 한 수로 확정돼도 반례가 없으면 → **그리디**([학습_그리디](학습_그리디.md) 2절)
- 지금 선택이 나중을 바꿔서 **여러 경우를 남겨 두고 조합해야** 하면 → **DP**

동전 문제가 좋은 예입니다. 배수 체계면 그리디가 통하지만([학습_그리디](학습_그리디.md) 5절), `[1,3,4]`처럼 그리디가 깨지는 동전에서 **최소 개수**를 구하려면 DP로 "각 금액까지의 최소 개수"를 채워 올라가야 합니다.

> **공통 감각:** "**완전탐색으로 풀면 되는데 같은 계산이 자꾸 겹쳐 지수로 폭발한다**"는 느낌이 들면 DP를 의심하세요. 그 겹치는 부분문제를 `dp[i]`로 정의해 저장하는 순간, 지수가 다항식으로 내려갑니다.

## 6. 자기 점검 질문 (문서 닫기 전 스스로 답해보기)

1. DP가 "완전탐색(DFS)의 낭비를 없앤 것"이라 할 때, 그 **낭비**란 구체적으로 무엇인가? 피보나치 트리로 설명해 보라.
2. DP가 성립하려면 필요한 **두 조건**은 무엇인가? 둘 중 하나만 있고 다른 하나가 없으면 각각 어떻게 되는가?
3. Top-down과 Bottom-up은 **채우는 방향**이 어떻게 반대인가? 계단 오르기 점화식을 두 방식으로 각각 어떻게 표현하는가?
4. 점화식을 세우는 **세 단계**는 무엇인가? 그중 "dp[i]의 정의"가 왜 가장 중요한가?
5. "최대/최소 비용"이라는 지문만 보고 그리디와 DP를 어떻게 구분하는가? 되돌아봄이 필요한지로 설명해 보라.
